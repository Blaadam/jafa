# Troubleshooting & FAQ

## Command errors

### `error: unexpected argument '...' found`

Every command rejects flags it doesn't recognize. Check the command's
[CLI Reference](./cli/init.mdx) page for the exact flags it accepts —
`-a`/`--all` is only supported by `build`, `open`, `deploy`, `sourcemap`, and
`pull`, for example, not `serve` or `dev`. Run `jafa <command> --help` to see
what a command takes.

### `"<name>" doesn't exist in ".../projects"`

The project name you passed doesn't have a matching folder under
`projects/` in the target workspace. Run `jafa new <name>` first, or check
you're pointing at the right `target-directory`. Every command exits non-zero
for this, so it's safe to rely on in scripts and CI.

### `"<name>" doesn't exist in ".../artifacts"` (from `jafa open`)

The project hasn't been built yet. Run `jafa build <name>` (or `jafa dev
<name>`, which builds first) before opening it.

### `invalid value '...' for '--groupid <GROUP_ID>'`

`jafa deploy`'s `-g`/`--groupid` must be digits only — it's written directly
into `mantle.yml`'s `owner.group`. Omit it entirely to deploy under your
personal account instead of a group.

### A tool "was not found" (`rojo`, `rokit`, `mantle`, `lune`, `wally`)

Jafa runs these tools but couldn't find one. Run `rokit install` in the
workspace root, and make sure Rokit's `bin` folder is on your `PATH`. Rokit's
tools only work inside a folder that has a `rokit.toml`, so run Jafa from
inside the workspace (or pass its `target-directory`).

### A command fails with the underlying tool's own error text

`jafa build`, `serve`, `sourcemap`, `deploy`, and `pull` run `rojo`,
`mantle`, or `lune` and judge them by their **exit code**. Warnings those
tools print are shown but don't fail the command. When one does fail, Jafa
prints the tool's error output; fix that and re-run.

### `"asset-updater.luau" doesn't exist in "..."` (from `jafa pull`)

`jafa pull` requires `asset-updater.luau` at the workspace root — it's
copied in by `jafa init`. If it's missing (for example because you deleted
it, or the workspace predates `jafa pull`), copy it back from a fresh
`jafa init` scaffold, or check you're pointing `target-directory` at the
right workspace root.

### `"..." is already a jafa workspace`

`jafa init` won't overwrite an existing workspace. Run it in a different
folder, or use [`jafa new`](./cli/new.mdx) to add a project to this one.

### `No universe "<name>" for "<env>"` (from `jafa deploy-universe`)

There's no `universes/<name>/<env>/mantle.yml`. Create one with
`jafa new-universe <name> -e <env>`, or check the environment name.

### Mantle fails right after "Deploying..."

Mantle needs to be authenticated with Roblox. Put your Open Cloud API key in a
`.env` file in the workspace root as `MANTLE_OPEN_CLOUD_API_KEY`, or follow
Mantle's [Authentication](https://mantledeploy.vercel.app/docs/authentication)
docs. Mantle's own error appears just above Jafa's.

### Linux warning from `jafa open`

`jafa open` (and therefore `jafa dev`) opens `.rbxl` files with `open` on
macOS, `start` on Windows, and `xdg-open` on Linux. Roblox Studio itself has
limited Linux support, so Jafa warns about it.

## `jafa init` ran but something's missing or broken

`jafa init` runs `git init`, `rokit install` and `wally install --project-path
./wally` if you agreed to them. If one fails, `init` prints a warning
(for example "`rokit install` failed, run it yourself later") and carries on, so the
workspace is still created. Check the output further up your terminal, fix
the problem (usually Rokit or Wally not being on your `PATH`), and re-run that
command from the workspace root.

## FAQ

**Where do `default.project.json`, `selene.toml`, and `stylua.toml` come
from?** They're part of each *project* Jafa creates under
`projects/<name>/`, not the workspace root — see
[Workspaces](./concepts/workspace.mdx) and
[Project structure](./concepts/project-structure.mdx).

**Do I need to run `jafa sourcemap` manually?**
No — [`jafa build`](./cli/build.mdx) already regenerates the sourcemap as
part of building. Run `jafa sourcemap` directly only if you want an
up-to-date `sourcemap.json` without doing a full build.

**Can I edit the generated `mantle.yml` directly?**
Yes. `jafa deploy` only manages `owner`, `payments`, the place file, the
place name, and `environments` — see [`jafa deploy`](./cli/deploy.mdx) for
exactly which fields it touches. Anything else (badges, social links, avatar
configuration, remote state) is left alone. Be aware that Jafa re-saves the
file when it updates it, which drops comments. A [universe](./concepts/universes.mdx)
config is never rewritten, so use that if you want comments to survive.

**Should I use `deploy` or `deploy-universe`?**
Use `deploy` to put one project somewhere you can test it alone. Use
`deploy-universe` for an experience made of several places. See
[Universes](./concepts/universes.mdx).

**Why did `jafa pull` fail with "Failed to get roblox auth cookie"?**
`jafa pull` runs a Lune script that calls `roblox.getAuthCookie()` to
authenticate with Roblox, which reads the cookie Roblox Studio stores
locally. Make sure you're logged into Roblox Studio on the machine running
`jafa pull`.

**Something's not covered here — where do I ask?**
File an issue on [GitHub](https://github.com/blaadam/jafa).
